File Naming Guide

You can put documents straight into a person's Google Drive folder, without going through the dashboard. When the file is named this way, the dashboard records it for you. This works for Staff Training, Annual Planning, Quarterly Reporting, Medical and Intake.

1. The rule

Code_Date.pdf

Intake is the one exception: there the name starts with the step number instead, e.g. 1.3 Photo ID.pdf.

  • Code is the document's code from the lists below. It goes first. Capital letters don't matter.
  • Date comes after an underscore _ (a space works too). Whether it's needed depends on the module: see the table in section 2.
  • Don't put the person's name in it. The folder already says who it's for.

3. What happens next

  1. The dashboard checks the folder whenever you open that person's screen, and checks everyone's folders every night (3:15 AM).
  2. A recognized file marks its item done. On the person's screen it's listed under Picked up from Drive, and the item shows the file name.
  3. A file it can't place is listed under Files in the Drive folder the app couldn't place, with the reason. Rename it in Drive and reopen the screen. (Files that were already in the folders before November 10, 2026 aren't listed, so older free-form names don't clutter the screen. Older files that follow this guide still count.)

Good to know

  • Renewals: for a yearly (or 2-year) training item, a file with a newer date replaces the one on file and moves the next due date. An older file is left alone.
  • Already on file: a one-time item, an Annual Planning document or a quarterly report that's already done is never changed by a second file.
  • Medical: a file attaches to a logged appointment of that type and date that has no document yet (and marks it Completed). Otherwise it's logged as a new completed appointment.
  • Intake: a step the candidate normally sends (an upload or a form) comes in as Received for you to Accept or Return, like their own uploads. Steps ASRS does (documents, trainings, meetings) are marked Complete. Nothing is emailed to anyone.
  • Items that don't apply to the person's role (e.g. a Sponsor-only item in a DSP's folder) aren't recorded. They show in the couldn't-place list.
  • Files the app created itself, and training-module certificates (Module_…), are recognized and left alone.

9. Adding a new document type

Staff Training: you can do this yourself in Notion

  1. Open the Training Requirements database in Notion and add a row.
  2. Fill in Label (what it's called), Part, Section, Applies To (Sponsor, DSP, Secondary DSP), Renews (One-time, 1 year or 2 years) and Order, and check Active.
  3. Give it a Key. This is the code for file names: letters and numbers only, no spaces, e.g. FireSafety. Pick it carefully: never change a Key once it's used. To rename the item, change its Label instead.
  4. Reload the dashboard. The item appears on everyone it applies to, and its code appears on this page.

To retire an item, uncheck Active. Don't delete the row.

Intake: you can do this yourself in Notion

  1. Open Intake Steps (Sponsor) or DSP Intake Steps in Notion and add a row.
  2. Give it a Key like the others: the stage number, a dot, and a number, e.g. 2.7. Use 3.A1 style for admin-only steps. Never change a Key once it's used.
  3. Fill in the Label, Stage, Type and Order as for the other steps, and check Active. The step number then works in file names and shows up here.

Annual Planning, Quarterly Reporting and Medical: ask Claude

These checklists are part of the app's code (Annual Planning documents also need two new columns in Notion). Ask Claude to add the document, giving its name and the code you'd like. The code shows up here once it's added.
